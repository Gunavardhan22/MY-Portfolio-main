About Me

From machine learning models to useful, reliable software.

I'm a Computer Science and Engineering student at SRM Institute of Science and Technology (2022–2026). I started with machine learning and deep learning: cleaning data, training models, and finding out where they fail. The more I built, the more I cared about what happens around the model: the API that serves it, the database behind it, and whether a person can understand the answer.

In my intrusion-detection project, I trained CNN and LSTM models, used a GAN to add samples for rare attacks, and added a Gemini step that explains each prediction in plain language. Wiring a model and an LLM together taught me more about prompts, failure handling, and secret management than any tutorial.

Now I'm focused on building LLM-powered applications in Python, evaluating them before trusting them, and deploying them behind reliable APIs. I'm looking for a team where I can contribute as a fresher, learn from experienced developers, and grow as an engineer.

Workflow

How a GenAI application works.

Two general architecture patterns I design around. They aren't a claim that every project above implements every step.

Typical LLM application

  1. 01

    User input

    Start from the task the user needs done.

  2. 02

    Input validation

    Check length, type, and intent first.

  3. 03

    Prompt or retrieval

    Build the prompt from instructions and context.

  4. 04

    Model / API call

    Server-side, with the key kept secret.

  5. 05

    Output validation

    Parse against a schema and check the claims.

  6. 06

    Response

    A clear answer, or a safe fallback.

Retrieval-augmented generation (RAG)

  1. 01

    Question

    What the user wants to know.

  2. 02

    Embedding

    Turn the question into a vector.

  3. 03

    Document retrieval

    Find the most relevant chunks.

  4. 04

    Grounded prompt

    Answer only from those sources.

  5. 05

    LLM response

    Generate the answer with citations.

  6. 06

    Citation and output checks

    Every claim traces to a source.

  • RAG vs. whole document Retrieval keeps prompts small and answers traceable, but only if retrieval finds the right chunks.
  • Quality vs. latency and cost A larger model isn't always worth the wait or the bill. Measure before choosing.
  • Confidence vs. evidence A confident answer isn't a correct one. Evaluate with test cases before trusting it.
